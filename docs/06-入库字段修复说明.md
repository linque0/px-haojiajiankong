## 口径调整：全文请求间隔可调 0–10 秒（0.1 秒步进）（2026-10-04，用户指令）

- 用户反馈扩展看板的「全文请求间隔（秒）」无法调整。原因：v0.4.5 建立的钳制链——输入框
  `min=2 max=15 step=1`（弹窗与看板同）、网关校验 `title_interval_ms` 整数且限
  2000–15000ms、客户端 `intervalFor`/`stats.interval_ms` 同口径钳制；低于 2 秒或小数
  值被逐层弹回，表现为"调不动"。
- 按用户指令改为 **0–10 秒、0.1 秒步进**：两处输入框 `min=0 max=10 step=0.1`；网关接受
  0–10000ms 数值（先按原始值判界再取整到 100ms 粒度——吸收 JS「秒×1000」浮点误差，
  0.1 秒粒度与界面步进一致，10001 不会被取整成合法值）；`title-source.js::intervalFor`
  与 `titles.js::stats.interval_ms` 客户端钳制同步，**0 是显式设置（不等待），不再当
  缺省值吞掉**（未提供/非法仍回落默认 3000ms）。
- 护栏不变（docs/10 §4.3）：每 8 次实际请求的暂停、整页结束后补采轮前至少 6 秒暂停、
  请求超时与重试上限、验证/限流即停，均不受间隔下调影响；间隔归 0 时这些暂停成为唯一
  兜底节流，如实保留。
- 扩展 v0.5.0 → **v0.5.1**（弹窗/ titles.js / title-source.js 变更走自更新；看板
  dashboard.html 由网关直接从磁盘提供，刷新页面即生效）。**网关校验在 Python 侧，
  需重启后台服务后新范围才生效。**
- 相关测试：网关范围/取整回归（test_gateway.py，0/10000/3500.4→3500/浮点误差取整合法，
  -100/10001/15000/非数字拒绝）+ 双 UI 与客户端钳制契约护栏（test_title_interval.py
  4 项）通过；未跑全量（按用户指示）。
