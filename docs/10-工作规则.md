# 10 工作规则 —— 本仓库的开发与维护纪律

> 生效：2026-10-04。适用：本仓库的一切开发、维护、文档与提交活动（人或 AI 助手均遵守）。
> 上位文件：docs/00（大方向与边界）仍是最高定位文件；本篇只规定"怎么干活"，不改变"干什么"。

## 1. 文档纪律

1. **编号递增**：`docs/NN-主题.md` 按序号新增，不复用旧号（当前缺口 04 为历史沿革，不补占位）；每篇文档头部注明定位与日期。
2. **交付必落档**：每项用户指令驱动的变更，在对应文档追加"改动 / 验收 / 诚实边界"三段；调查与实验（不改代码）同样落档（如 docs/07、08）。
3. **诚实边界必填**：每份交付写清"验证了什么、没验证什么、不能声称什么"；实测结论与推测分列，不把猜测写成事实。
4. **变更台账**：docs/09 是跨会话变更总览，每完成一批工作后更新其"变更总览"表并链接对应文档。
5. **本地备份不入库**：`*.bak.md` / `*.bak.yaml` / `*.bak.py` 仅供本机留档，已在 .gitignore，不提交。

## 2. Git 纪律

1. **分组提交**：按逻辑单元提交（构建 / 词表 / 分析 / 扩展功能 / 文档），不把不相关变更混在一个提交；确有跨主题文件时在提交信息中说明。
2. **提交信息**：中文，`类型：摘要` 格式（参照现有：`初始化：` `构建：`；常用类型——构建、词表、分析、扩展、网关、文档、测试）；正文可列要点，写"为什么"而不只是"改了什么"。
3. **提交前三件事**：① 全量 pytest 通过；② `git status` 核对无红线文件被暂存；③ 新增文件确认应入库（产物/数据不入）。
4. **绝不入库清单**（.gitignore 已覆盖，提交前人工再核一遍）：
   - 登录态与凭据：`data/state/storage_*.json`（含站点 Cookie）、任何认证头/Cookie/验证码参数；
   - 采集产物：`data/raw/`、`data/runs/`、`data/logs/`、`data/analysis/`、`*.duckdb*`；
   - 本机配置：`config/paths_override.json`；工具状态：`.mimosa/`、`.zcode/`；
   - 本地备份：`*.bak.*`。
5. **换行**：由 `.gitattributes` 统一（仓库内 LF；`.bat/.cmd` 为 CRLF）。检出告警 "CRLF will be replaced by LF" 属正常，不需处理。
6. **历史不改写**：main 分支只前进；发现错提交用新提交修正并说明，不 rebase 已有历史。

## 3. 测试纪律

1. **离线优先**：回归一律离线运行（夹具 + mock），不访问站点；pytest 全绿是提交门槛。
2. **夹具来源**：新选择器/解析逻辑用真实 DOM 校准，夹具只保留公开字段（认证头、Cookie、校验参数一律剔除），并注明采集日期（如 `real_hover_titles_pxb7_20261004.html`）。
3. **行为改动必须带回归**：修 bug 先写重现该 bug 的用例；新功能带正例与反例（否定/页脚/串号等边界）。
4. **多运行时**：扩展 JS 逻辑同时有 pytest 包装测试与 Node 驱动（`tests/direct_titles.cjs`），协议改动两边同步。

## 4. 采集合规红线（继承 docs/00 §5 / docs/01 §3，此处汇总执行口径）

1. 不做指纹伪造、打码、协议逆向、代理池；Playwright 自动化通道被 WAF 拦截期间不试探恢复，走插件通道。
2. 出现验证码/滑块/访问验证：立即停止相关采集，保留已入库数据与待补清单，不绕过、不重试施压；429 遵守服务端恢复时间（能读 `Retry-After` 才用，不可猜）。
3. 限速与退避档写死在代码/配置，登录态不放松；任何"提效"改动不得突破已写死的档位，调参需证据（docs/07 四阶段）。
4. 插件"零新增请求"指被动读取模式；补标题/加载更多属主动请求，必须：单并发、限速、遇验证即停、失败有界、不重发已成功的请求。
5. 不采集卖家个人身份信息；不自动下单、不代购、不撮合。

## 5. 数据与口径诚实

1. 不编造：采不到的字段保持空值或保留失败状态，不填 0、不伪装成功；推断必须标注推断。
2. 计数防串号：角色/武器数量、链数、精炼条目数与命名条目交叉校验；"详情看图/官方截图"等明确结尾才作完整性判据。
3. 样本不足不发布：看板周聚合/价格带遵守 `min_cell_sample` 门槛。
4. raw 可复核：影响入库口径的修复，提供离线重放/修复工具（如 `tools/repair_listing_fields.py`），改前备份、事务写入、价格与采集时间不变。

## 6. 变更工作流

提案 → 对照 docs/00 §1 两个目的（服务不了的不做）→ 实施 → 回归全绿 → 落文档（含诚实边界）→ 更新 docs/09 台账 → 分组提交。

## 7. 安全钩子（Mimosa）处置规则

1. 提交被拦截时先读结论与证据，区分"真实风险"与"架构性误报"。
2. 真实风险：修复后重扫，修复过程与结果写入对应文档。
3. 确认误报（如：内容脚本驱动 MAIN 世界请求固定公开端点、URL 为模块常量且入参有白名单校验、background 已有端点白名单）：按钩子流程运行官方扫描形成记录，并在本文件或对应文档补记误报理由；不为过扫描而掩盖真实风险，也不因误报搁置合规的正常工作。
4. 安全边界不变式：本机网关只绑回环；登录态/认证头不出现在扩展与网关之间的传输与落盘中；扫描覆盖不完整时不得声称"项目安全"。
