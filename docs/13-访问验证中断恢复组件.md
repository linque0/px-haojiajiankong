## 改动

扩展升级为v0.5.4。在运行目录v0.5.3代码基础上增加`verification.js`，保留独立详情间隔与重复商品计数功能。权限、回环网关和单工作标签页不变。

组件识别真实页面出现的阿里云滑块、旧版滑块和访问验证容器，并沿祖先检查隐藏状态；SDK样式、隐藏祖先及空组件不作为正在验证。扩页前后、标题请求前、详情就绪检查和上传前均设置闸门。检测到验证就停止主动采集，后台保存`waiting_verification`状态，保留当前商品、原始轮次、成功数及待采队列，清除超时报警并显示需要验证的标签页。验证不消耗当前账号，不计为失败，不进入下一账号。

用户在网站完成验证后，组件只观察DOM；验证稳定消失1秒后恢复原任务。网关拒收但页面未观察到挑战时，不定时重复提交；可在扩展弹窗点击“验证已完成，继续”，组件再次检查可见验证和稳定状态后续采。页面仍显示验证时该按钮拒绝继续。等待期间仍可取消任务；任务状态与详情队列落入扩展本地存储，后台重启和原页刷新后可以恢复等待任务。页面地址改变、错标签页、旧详情结果不能恢复或覆盖原任务。仅连续网络失败的既有暂停逻辑保持原样。

本组件负责验证中断恢复。网站滑块仍由用户完成；没有模拟拖动、验证码识别、验证码参数读取、验证状态修改、自动刷新挑战页或绕过验证的代码。

## 诚实边界

测试中的验证解除由夹具模拟用户完成，不能写成自动破解验证码，也不能据此声称真实网站已通过验证。现有Chrome页上此前的鼠标拖动未成功，真实验证由用户手动完成。扩展文件写入磁盘后，浏览器需应用扩展更新并刷新源页，才能运行新内容脚本；旧已加载脚本不会被磁盘修改即时替换。

采样开发期间已关闭新的自动启动；本组件不更改详情间隔配置。此前Y04、Y02均以0.4秒间隔完成64条详情、条件及原轮次价格核对，共128个跨任务唯一账号、相对冻结318条基线净新增116个。同步时现场网关间隔已为0.8秒，本次组件同步未写入该设置。新组件不把这些历史完成数据重新计为新增。

## 取消后重采修复（2026-10-06，v0.5.5）

### 改动

- 后台显示取消时，源页可能仍等待当前全文请求或验证观察退出。旧代码立即拒绝新采集，提示“本页已有采集任务进行中”；现在重采等待旧操作结束再开始，不提前重置取消标志，不让旧操作提交或清理新任务。
- 取消消息携带任务编号；源页在仍执行其他编号的任务时拒绝过期取消消息，同时清理人工验证确认标志并更新页内角标。
- 取消详情工作页后显式激活原列表，防止浏览器选择其他网站导致“采集本页”无效。源页已关闭时安全忽略激活失败。
- 扩展版本升为0.5.5，首次应用扩展更新后刷新源列表，使内容脚本更新；之后取消重采无需刷新页面。

## 真实扩展自动启动、滑块通过与10账号验收（2026-10-12）

### 结果

真实Chrome中的v0.5.13扩展自动启动后自然出现阿里云访问验证。用户在出现验证后明确同意“一次自动拖动”；浏览器工具执行一次拖动，网站当场显示“验证通过!”，原列表加载恢复，扩展自行启动详情队列，最后显示“详情队列全部入库完成”。本轮净新增10个鸣潮官服账号、10条快照，成功详情入库10个；逐账号只读核对缺项0、重复快照0、列表挂牌价与原轮次快照一致10/10。

这证明当前浏览器环境下，真实扩展的单批启动、访问验证识别、一次普通滑块交互及通过后的自动续采可运行。没有七天结果，没有所有区服覆盖或全市场更新周期证据；单次通过不能证明长期无人值守。

### 启动方式与现场

- 保留原源页`https://www.pxb7.com/buy/10302/1#wuwa-research-V2-B01-supplement`、官服筛选和已有队列保护。网关可达，已加载扩展与磁盘版本均为0.5.13。

- 保留详情间隔200ms、标题间隔3000ms、串行队列、5分钟同页自动去重。出现验证后立即将`auto_ingest`恢复false，目标10持久保留；关闭新的自动触发不会取消已启动任务。没有降低间隔、清空去重或重复启动施压。

### 本地候选与研究结论

| 方案 | 当前结论 | 尚缺的证据 |
|---|---|---|

## 可配置普通滑块自动处理（2026-10-13，v0.5.14）

### 改动

用户明确要求修改规则与运行代码，并确认“两者都修改”。docs/00、docs/01、docs/10和docs/27已取消遇验证只能等待人工的限制，允许研究减少验证触发与自行完成验证。自动处理采用当前真实浏览器中的普通输入；数据完整性与商品身份校验仍是入库条件。

网关新增`verification_mode`枚举：`manual`为默认，`auto_slider`为自动尝试。扩展弹窗和完整采集看板均可设置。选择自动模式后：

1. 可见挑战出现，保存原任务、当前商品、轮次和队列，保留`waiting_verification`状态以保护进度；不把等待状态解释为禁止自动处理。
2. 后台重新核对配置、发送者扩展ID、顶层frame、任务ID、源页/工作页地址及详情nonce。任务中持久化`autoAttempted`，同一次等待事件仅尝试一次，刷新或Service Worker重启不能重复消费。
3. `slider-input.js`只接受pxb7列表/商品页面。使用固定的只读函数重新取得公开控件几何；只支持`#aliyunCaptcha-sliding-slider`和明确“拖到最右”文字的普通滑块。隐藏、遮挡、越界、错页或不支持的形态拒绝输入。
4. 通过Chrome Debugger的Input发送一次普通匀速拖动，约540ms；不伪造设备/人类轨迹，不修改DOM、验证状态或验证结果，不读取验证码参数/Cookie，不复制身份凭据。输入过程中检查取消、任务变化与URL；结束时释放鼠标并断开自己的调试会话，不能断开别人已持有的调试器。
5. 回执`inputSent`只表示输入完成。观察器仍等可见验证稳定消失1秒，再恢复原任务；现有详情ID、标题和入库校验继续执行。失败、形态不支持或调试器不可用时，保留现场供人工完成，不自动刷新/反复拖动/跳到下一商品。

详情工作页原先没有在开始前读取配置，现已先加载配置，以便应用验证策略。暂停回执返回新nonce，内容脚本在自动输入前更新关联值，旧详情消息不能发起输入。网关拒收但页面未显示挑战时仍等待实际挑战或明确确认，不执行盲目坐标操作。

### 权限与使用

Chrome官方说明`debugger`不能作为optional权限，清单因此增加必要的`debugger`声明；此权限能力较广，实际代码仅在核对后的当前采集标签页短暂附着，用Runtime读取上述公开几何并发送Input命令，没有增加网络/存储/截图监听。原回环host权限和内容脚本匹配范围保持。调试器附着时浏览器会显示调试提示；DevTools或其他调试器占用、企业策略限制等可能导致自动输入不可用。[Debugger文档](https://developer.chrome.com/docs/extensions/reference/api/debugger)、[权限文档](https://developer.chrome.com/docs/extensions/reference/api/permissions)

启用步骤：重新启动采集网关以加载新配置枚举，应用扩展v0.5.14更新并按浏览器要求接受权限，刷新列表/工作页；在扩展弹窗或完整看板选择“自动尝试普通滑块一次”并保存。默认配置不会静默改为自动模式，现有生产配置和正在运行的任务没有在本轮被改写。油猴未接入此策略；传统CLI的24小时闸门也未改为浏览器输入策略。

## 不依赖AI的独立程序入口（2026-10-14）

### 改动

新增 [tools/pxb7_slider.cjs](../tools/pxb7_slider.cjs)，使用Node 22及以上自带的Fetch/WebSocket连接专用Chrome的回环CDP；无AI、BrowserAct、打码服务或额外npm依赖。复用扩展的`slider-input.js`，以固定公开DOM取得当前坐标，进行一次普通水平拖动。它不启动/重启浏览器，不修改页面、认证状态或验证码返回值。

提供单次执行与有截止时间的观察模式。每个可见普通滑块事件仅执行一次；验证组件消失且业务页面稳定恢复1秒后，下一次阻断才允许再执行。网站拒绝、业务未恢复、页面变化、调试器断开、不支持的形态或取消时退出/保留现场，不刷新挑战或无限重试。普通输入方法与本次成功浏览器操作相同，但18步、约540ms的程序输入节奏不等于浏览器工具的内部拖动实现。

结构化回执区分`inputSent`、`verificationCleared`、`businessReady`。业务恢复探针只检查可见列表价格卡片，或当前详情编号与价格/详情文本；它不代表全字段采集验收，不执行入库、续采、导航或启动新采集任务。既有扩展任务仍由原队列按配置处理验证与恢复，不需要此CLI配合。

### 使用

日常采集优先使用现有扩展：启动网关、应用扩展更新、刷新业务页面，在设置中选择“自动尝试普通滑块一次”并保存，再启动采集任务。扩展运行无需AI或本CLI，也不要求开放CDP端口。

独立研究程序适用于**已经启用回环CDP的专用Chrome**。不能与扩展自动验证、DevTools或另一个输入程序同时操控同一页。Chrome 136及以后要求非默认`user-data-dir`；不要把个人默认浏览器资料复制到研究配置。参见[Chrome官方说明](https://developer.chrome.com/blog/remote-debugging-port)。本次没有替用户开放端口或改变浏览器启动方式，当前9222端口不可达；CLI真实网站执行尚未验收。

在项目根目录执行：

```powershell
node tools/pxb7_slider.cjs --help

# 查看专用调试浏览器的目标；选择实际需要处理的pxb7页面id。
Invoke-RestMethod http://127.0.0.1:9222/json/list |
  Where-Object { $_.type -eq 'page' -and $_.url -like 'https://www.pxb7.com/buy/*' } |
  Select-Object id, url

# 将示例targetId替换为上一步实际id。
node tools/pxb7_slider.cjs --cdp http://127.0.0.1:9222 --target ACTUAL_TARGET_ID

# 限时观察同一标签页；进程在失败后退出，不自动重启。
node tools/pxb7_slider.cjs --cdp http://127.0.0.1:9222 --target ACTUAL_TARGET_ID --watch-seconds 3600

# 离线回归，可重复运行，不访问网站。
node tests/slider_runner.cjs
```

退出码0为执行/观察正常结束，2为验证或业务恢复未完成，1为参数/连接失败。观察时间结束的0不表示这段时间完成过验证；核对实际JSON回执。进程状态不跨CLI重启持久化；手动再次运行是一次新的显式执行。扩展队列已有的单次尝试标记则跨Service Worker重启保留。
