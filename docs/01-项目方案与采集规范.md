## 1. 项目定位与业务问题

最终目的与大方向见 [00-大方向与产品形态](00-大方向与产品形态.md)：趋势监控（时间维度决策）与购买策略（单品维度决策）双目标，本方案的管线与指标服务于两者。具体拆为三类真实决策：

| 决策 | 使用者 | 依赖模块 |
|---|---|---|
| **捡漏买入**：哪些账号显著低于合理价 | 买家 | 合理价模型 + 捡漏信号（A1） |
| **卖出定价**：我的号挂多少、何时挂 | 卖家 | 价格指数 + 去化速度 + 模型预测 |
| **市场观察**：账号价格波段、供需节奏 | 研究 | 价格指数 + 供给/去化时序 |

**边界（写死）**：只做价格研究与市场观察；不做撮合、代购、自动下单；不抓取与价格无关的卖家个人身份信息；分析结论不做投资建议。

**与竞品的关系**：ai-goofish-monitor（闲鱼监控，14.6k★）验证了"浏览器自动化采集 → 规则/LLM 分析 → Web 后台 → 推送"闭环；本项目把其中"LLM 判断相关性"替换为"结构化属性 + 统计模型"——因为螃蟹的挂牌属性高度结构化（实测确认），统计模型比 LLM 过滤更准且零 token 成本。开源界目前没有"会员购/账号平台销量价格时序分析"方向的成熟项目，方向是空白。

## 2. 站点实测结论（2026-10-02 浏览器实测，采集方案的依据）

- **robots.txt**：`User-agent: *` 下 `Allow: /`，仅禁 `/_nuxt/`、`/assets/`；提供 sitemap（`/sitemap/sitemap-index.xml`）→ 公开挂牌页对爬虫开放。
- **URL 规律**：列表页 `/buy/{gameId}/{bizProd}`（bizProd=1 账号，4 道具，2 充值）；详情页 `/product/{listingId}/1`；游戏 ID 实测（2026-10-02 选游页逐一点击确认）：二游系 原神 10026 / 崩铁 10161 / 绝区零 10312 / 鸣潮 10302 / 异环 10630 / 终末地 10605；射击系 三角洲 10371 / 暗区突围 10110 / 和平精英 10011 / PUBG 10021 / CODM 10052 / 无畏契约 10148 / CF 10039 / CF手游 10033 / APEX 10050 / 永劫无间 10023 / 逆战未来 10460；其他 王者荣耀 10013 / 英雄联盟 10012 / LOL手游 10036 / 火影忍者 10032 / 第五人格 10059 / 超自然行动组 154643349307491 / DNF 10025 / 逆水寒手游 10163 / 蛋仔派对 10142 / 光遇 10040。完整分类与词表见 docs/02 §2/§4。
- **列表卡片字段（结构化，实测原样可得）**：价格（¥）、发布时间（"21分钟内发布"）、等级、黄数、主角性别、五星角色数、五星武器数、纠缠之源、原石、圣遗物数、时装数、区服（官服/B服/小米服/国际服及子区）、邮箱状态（出售/实名/注销等 8 态）、TAP/PSN 绑定、换绑码、找回包赔、官方验号、图片数、特色角色名。
- **筛选器即属性字典**：价格区间 / 冒险等级 / 五星角色数量 / 黄数 / 原石 / 纠缠之源区间，排序（综合/最新/价格/收藏）——直接作为采集任务的配置 schema。
- **详情页**：有"正在浏览"人数（游客态打码；登录态取完整值——v1.3 登录态优先的主要增益之一）与收藏；**成交价不公开**。
- **接口层陷阱**：列表数据走 `api-pc.pxb7.com/api/search/product/v2/selectSearchPageList`，请求携带 `timestamp__1366=` 加密签名参数（社区已有 JS 逆向演示视频）。**本方案不逆向该签名**（见 §3 红线）。
- **规模**：平台自报当前在售 9,807,291 个账号 → 全量采集不可行也无必要，靠任务切片只采目标子集。

## 3. 采集姿态与合规边界（v1 调整：登录态放行；协议逆向仍不做）

### 3.1 允许的采集方式（正路）—— v1.3 登录态优先

1. **Playwright 驱动真实浏览器渲染**：加载列表页/详情页，解析渲染后的 DOM 卡片。与真人浏览等效，不触碰签名算法。
2. **登录态优先（v1.3 调整，原"游客态优先"作废）**：采集任务默认以自有小号的**持久化登录态**运行（登录一次保存 `storage_state` / 常驻 user profile 复用）。
   - 数据全面性增益：详情页"正在浏览"完整数值（游客态打码）；更高单页条数与更完整筛选选项（**待 W1 实测**——2026-10-03 诊断：新鲜游客态/无头浏览器被 WAF 滑块拦截，登录态或已建立会话可正常访问，登录态为**必需前置**而非增益项；列表页卡片已实测到 collectcount 收藏数语义属性）；如登录态下可见收藏/想要人数等需求侧字段，一并采集（**待实测**）。
   - 获取便利性增益：会话持久化免重复初始化；平台对登录用户的正常浏览通常更宽容（游客高频浏览更易触发风控）。
   - 账号纪律：专用买家小号（非主力账号）；**主备双小号冗余**——主登录态失效切备用并降频，**不并发轮换、不加压规避风控**；登录态文件不入 git、不外传。
3. **游客态 = 降级通道**：仅当主备登录态均失效/被风控时使用；降级期间采集口径变窄，`collected_via=guest` 如实标注（数据缺口记录，不伪造）。
4. **模拟人类节奏的限速（不变）**：单页间隔 3–6s 随机；任务间 ≥60s；每任务每轮 ≤5 页；每任务每日 2–4 轮（捡漏监控任务可加密轮次但缩小页数）。**登录态不用于放松限速**——只解锁数据可见性，不加大请求压力。

### 3.2 不做的（红线，理由如实记录）

- **不做协议层逆向**：不破解 `timestamp__1366` 签名算法、不在浏览器外直连加密 API、不用打码平台过验证码、不做指纹伪造与代理池轮换规避封禁。
- **理由**（司法风险，非道德姿态）：国内已有"车来了"案（伪造请求参数爬取数据，非法获取计算机信息系统数据罪获刑）及新浪微博诉脉脉、淘宝诉美景等不正当竞争判例——逆向签名 + 规模化直连正处于该风险区间；且 §2 实测表明浏览器渲染路径已可获得全部分析所需数据，逆向仅是规模优化，风险收益比极差。
- **风险决策记录**：用户 2026-10-02 明确要求放开反爬绕过；本文档仅放开至"登录态 + 浏览器自动化"，协议逆向仍排除——若未来需要更高吞吐，正确路径是谈数据合作或降低分析粒度，不是逆向。

### 3.3 风控退避（写成采集器硬逻辑，不是文档口号）

| 触发信号 | 动作 |
|---|---|
| 出现验证码/滑块 | 立即停采该任务，24h 后以 1/4 频率试探恢复；连续 2 次 → 停并告警 |
| 请求被拒/空响应率 >30% | 当轮终止，退避 6h |
| IP 被封（整站不可达） | 停止采集，人工介入 |
| 主登录态被风控/踢出 | 切换备用登录态，频率降至 1/2；备用亦失效 → 降级游客态 + 72h 观察后人工换号；不连续重试登录 |
| 登录态运行纪律 | 限速档与游客态完全一致（登录只解锁可见性，不加压）；同一登录态不做多任务并发 |
| 站点改版（卡片解析成功率 <80%） | 采集继续但只入 raw 层，解析告警，等修复 |

- **幂等**：`(snapshot_at 截断到轮次, listing_id)` 唯一；同一轮次重跑先删后插。
- **bronze/silver**：原始 DOM dump 落盘 `data/raw/pxb7/{task}/{date}/`（排障与重解析用）；解析后入 silver 快照表。解析器带 `parser_version`，站点改版可重放 raw。
- **关键口径披露（进入看板横幅）**：挂牌价 ≠ 成交价；下架 ≠ 一定成交（可能是撤牌/平台下架）；"在售消失"只作为成交的**推断**口径，写作 delist 而非 sold。

## 5. 指标体系

| ID | 指标 | 定义 | 备注 |
|---|---|---|---|
| M1 | 挂牌价格指数 | 分 游戏×区服×价格带 的挂牌价中位数，链式周指数 | 样本数 <30 的格子不发布（不伪造） |
| M2 | 合理价模型 | 分游戏 hedonic 回归：ln(价格) ~ 等级+黄数+五星角色+五星武器+原石+纠缠+圣遗物+时装+区服+保障标签+特色角色哑变量 | 每周重训；披露 R² 与分位误差；训练样本不足时不出模型 |
| M3 | 捡漏分 deal_score | ln(实际挂牌价 / 模型预测价) 的子域横截面分位 | <P5 强信号；只在 price_band ∈ {floor, low} 内出信号（v1.1）；模型不可用时不出分 |
| M4 | 去化速度 | 各价位段在售天数分布、周 delist 率（推断成交节奏） | delist 口径如 §4 披露 |
| M5 | 需求侧代理 | 详情页"正在浏览"（登录态完整值）、收藏数 | 仅对监控任务命中的 listing 采集详情页 |
| M6 | 供给节奏 | 新上架数/日、新上架价格分布、任务命中量 | 筛选器配置变化前后不可直接比较 |
| M7 | **号价变化趋势**（v1.1） | 两层：①**单账号价格轨迹**——降价阶梯（次数/幅度/间隔）、重挂检测、在售天数×当前价的去化压力；②**市场价格趋势**——M1 指数扩展到 游戏×区服×价格带×关键词段（如"满命段/典藏段"）周链指数，4 周动量映射 rising/peak/declining 阶段（复用 IP 项目 phase 逻辑，阈值 ≥12 周后校准），版本/卡池/赛季/追缴事件的窗口跳变（事件研究），供给突增×价格下移 = 抛压信号 | 输出周趋势简报（白话版，推 webhook）；指数/阶段子域样本 <30 不发布；全部结论限定挂牌价口径（§4 披露） |
| M8 | **高价/底价判定**（v1.1） | 双层：统计层 = 子域内 hedonic 残差分位 → price_band（≤P10 底价 / ≥P90 高价带）；锚点层 = ceiling/floor 词表命中 → 天花板域/地板域分域与折价修正 | 详细规则与跨游戏价值五因子体系见 docs/02 §5/§6；输出含归因明细；捡漏信号只从 floor/low 带出 |

QC（每日自动，结果进通知）：价格非负、快照断档 ≤36h、卡片解析成功率 ≥80%、关键字段缺失率、listing_id 去重校验。

## 6. 预警与推送

| ID | 规则 | 触发条件（白话） | 动作 |
|---|---|---|---|
| A1 | 捡漏提醒 | 新上架账号 deal_score < P5 | 推送：价格/关键属性/模型预测价/链接 |
| A2 | 降价提醒 | 同 listing 降幅 ≥10% 或 ≥500 元 | 推送 |
| A3 | 市场热度 | 某游戏×价格带×关键词段 去化天数中位数周环比骤降 >30%，或抛压信号（供给突增×价格下移） | 推送市场信号（M7 输出） |
| A5 | 趋势转折 | 关键词段指数 4 周动量翻负（rising→declining）或追缴/赛季重置类事件日 | 推送趋势简报（白话版，M7） |
| A4 | 采集健康 | 解析成功率低 / 连续失败 / 登录态过期 / 触发风控退避 | 运维告警（区别于业务预警，发不同渠道） |

去噪沿用现有引擎惯例：同 listing 24h 冷却（`alert_history` 表）；A4 抑制 A1-A3（数据源不健康时不发业务信号，只报根因）。推送渠道：飞书/钉钉群机器人 webhook。

## 7. 看板设计（Streamlit，复用现有组件与白话层）

- **页 1 市场总览**：M1/M7 价格指数与趋势（分游戏切换，可下钻到区服×价格带×关键词段；rising/peak/declining 阶段着色 + 事件竖线）、M6 供给时序、M4 去化分布；顶部"三步看懂"+ 口径披露横幅（挂牌价≠成交价、下架≠成交、个人研究用途）。
- **页 2 捡漏雷达**：deal_score 升序表（价格/关键属性/模型预测价/price_band/归因词/链接），按游戏×关键词段筛选；模型不可算时显式留空并说明。
- **页 3 单游戏详情**：价格分布箱线图（分价格带）、属性-价格散点（选属性轴）、模型预测 vs 实际校准图、去化曲线、**单账号价格轨迹**（降价阶梯 + 事件线，v1.1）。
- **页 5 趋势周报**（v1.1）：各关键词段指数走势 + 阶段判定 + A5 转折信号的白话简报，可直接转发。
- **页 4 任务管理**：dim_task 列表 + 各任务健康度（最近成功、解析成功率、命中量）。
- 沿用 interpret 白话模式：每个指标配"这是什么现象、该做什么"。

## 8. 排期与验收

## 9. 风险登记

| 风险 | 等级 | 应对 |
|---|---|---|
| 站点风控升级（登录墙/强验证码） | 高 | §3.3 退避硬逻辑；最坏情况降频至每日 1 轮或停采，不做绕过 |
| 页面改版导致解析失效 | 高 | parser_version + raw 落盘可重放；schema 校验告警 |
| 登录态账号被封 | 中 | 专用小号；被封即 72h 观察，不连续重试 |
| ToS 禁止自动化采集 | 中 | 个人研究、限速、游客态优先；不做商业转售；必要时降低采集面 |
| 成交价不可得 | 固有 | 全部结论限定挂牌价口径；去化作为成交推断并披露 |
| 数据量过大（980 万在售） | 中 | 任务切片只采目标子集；不做全量扫站 |
