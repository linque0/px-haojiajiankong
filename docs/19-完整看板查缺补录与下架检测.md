# 19 完整看板查缺补录与下架检测

> 定位：扩展 v0.5.8 的使用说明、数据口径与验收记录。日期：2026-10-06。
> 前置：docs/17（查缺补录）、docs/18（缺失数据删除）。

> 2026-10-07 口径更新：v0.5.9 将额外付费商品排除出必填检测，未采到或为空不再判缺失；下文为 v0.5.8 历史记录，当前规则见 [docs/20](20-额外付费商品缺失判定修正.md)。其他检测规则保持。

## 改动

### 完整看板新增"信息查缺补录"区块（与弹窗功能一致）

`extension/dashboard.html`（网关 `http://127.0.0.1:8765/` 伺服）新增区块：

- 自动查询缺失清单：游戏筛选（已勾选游戏/全部/单游戏）、检测范围说明、每页 10 条分页、
  行内编号链接/游戏/轮次/缺失原因/最近补录状态。
- 跨页勾选、"全选/取消全选"切换、勾选本页补录失败／未补齐、"补录选中"（经网关备份后排队）、
  "删除选中"（confirm 列出编号 → 删除全部轮次）、"重试同步数据表"。
- 自动刷新 15 秒 + 手动刷新；排队任务状态独立显示（等待扩展领取/扩展执行中/启动失败）。
- 补录执行仍依赖扩展：完整看板发起的任务由扩展后台空闲时领取（chrome.alarms 每分钟轮询 +
  SW 启动即查），领取后复用现有补录队列、互斥、验证暂停与取消机制。

### 网关任务中转与补录结果台账

- 中转接口（仅本机来源）：`POST /backfill/enqueue`（复用 prepare 校验与备份后入队）、
  `GET /backfill/job`、`POST /backfill/job/claim`、`POST /backfill/job/finish`、
  `POST /backfill/result`（扩展上报单项结果）。任务为网关内存态，网关重启即清空，看板可重新发起。
- 台账 `data/state/backfill-results.json`：`/ingest/detail` backfill 回执与扩展上报的单项结果
  写入；`/backfill/candidates` 每行附 `last_backfill`；删除事务成功后清理对应条目。
  弹窗与完整看板共用同一份"最近补录"状态，弹窗本地记录仍优先。

### 鸣潮查缺与其看板列对齐（用户指令：先只做鸣潮）

鸣潮（10302）按看板列逐列判定，单元格为空即缺失（与 `_fmt_wuwa_cells`/dashboard 同口径）：

| 看板列 | 判定 |
|---|---|
| 等级/黄数/五星角色/五星武器 | 既有 valid_count（0 是有效值） |
| 共鸣链（N命）/武器精炼（精N） | 数量 >0 须有有效具名名单且与数量匹配；数量 0 不要求明细（既有 0 值纪律） |
| 资源 | 五件套（星声/月相/余波珊瑚/浮金波纹/铸潮波纹）键全部缺失才记缺失；采到 0 是值 |
| 额外付费商品 | 三键（车架模组/摩托饰品/人物皮肤）全部缺失才记缺失；提取器在段落存在但为空时写空列表（"已核为空"），确实没有付费商品的账号补录后可消缺 |
| 区服/商品发布时间/收藏 | 快照列（server/publish_time_text/favorites_cnt）NULL 记缺失 |

其他游戏维持原规则（原神/火影/三角洲等），后续可按需扩展。孤儿快照（快照在、`dim_listing`
档案缺失）改为可见（LEFT JOIN），game_name 回退"未知档案"，可被删除；不混入单游戏筛选与统计。

### 下架检测（扩展）

- content.js 新增 `detectDelisted()`：详情标题约 3 秒仍未就绪时，检查页面下架标记
  （`document.title` 与 `.product-detail` 区块内的"商品已下架/商品不存在/商品已删除/商品已失效"
  等文本），标记连续 2 次稳定才判定，返回错误码 `delisted`；不确定则维持原 20 秒超时路径，
  不误判加载中的正常页。
- 队列对 `delisted` 的处理：计入 failed/processed 并记录补录结果（本地 + 台账上报），**不计入
  连续失败**——连续多个下架商品不再触发"连续 3 张失败"整队暂停；队列 phase 显示
  "商品已下架，已跳过并标记补录失败"，结束汇总显示"下架跳过 N 个"。下架商品不会自动删除，
  保留在查缺清单中由用户手动删除。

### 弹窗"补录全部"改为"全选/取消全选"（用户指令）

- 全选：拉取当前筛选范围全部页（limit=200 循环）并入跨页选择；再次点击清空全部选择。
- "补录选中"仅发送已启用采集目标的记录，未启用项跳过并在提示注明（按钮启用条件从
  "全部可补录"改为"至少一条可补录"）；网关侧校验不变。
- 强制刷新：`refreshBackfill(force)` 在在飞查询期间置 dirty、结束后补跑一次——修复删除/
  启动后的刷新被 `bfLoading` 重入锁吞掉、要等 10 秒定时器才生效的问题。删除成功后即时从
  当前页移除已删行再强刷；prepare/delete 返回 `selection-changed-refresh-list` 时自动强刷、
  清空旧选择并明确提示"未删除任何数据，请重新勾选"。

## 使用

1. 扩展点"应用扩展更新"至 v0.5.8；网关已随代码更新（重启后生效）。
2. **完整看板**：打开 `http://127.0.0.1:8765/` → "信息查缺补录"区块，筛选游戏、查看缺项；
   勾选或全选后点"补录选中"——网关自动备份并排队，扩展（浏览器在线、空闲时）每分钟内领取执行。
3. **扩展弹窗**：功能不变，"补录全部"按钮已替换为"全选/取消全选"切换。
4. 删除：弹窗或看板勾选后"删除选中"，确认框列出编号；删除效果即时反映在清单。
5. 删除/补录后 CSV 同步失败（文件被占用）时点"重试同步数据表"。

## 验收

- Python（临时库）：鸣潮看板列逐列判定（资源全缺/0 是值、付费全缺/空列表已核为空、
  区服/发布时间/收藏、0 值纪律、其他游戏不受影响）；孤儿快照进清单且可删除、不混入游戏统计；
  台账注记与删除清理；中转任务 enqueue→job→claim→finish 状态机、不可重复领取、无效上报拒收；
  HTTP 来源校验（enqueue/result/claim 拒绝 pxb7 网页来源）。相关 54 项通过。
- Node（实际模块）：连续 5 个下架商品不停队、逐项标记 failed/delisted、`reportResult` 上报；
  content.js 下架 DOM 夹具判定 `delisted`、无标记页仍走超时路径（`tests/content_delist.cjs`）；
  弹窗全选切换、未启用项过滤、清单变化自动强刷清空、在飞查询期间删除后强刷不被吞
  （`tests/backfill_popup_delete.cjs`）；队列下架/中转领取（`tests/backfill_queue.cjs`）；
  完整看板区块渲染/全选/排队/删除/任务状态（`tests/dashboard_backfill.cjs`）。
- 全量回归与 `git diff --check` 见本仓库最终回归记录。

## 诚实边界

- 下架判定基于 DOM 文本特征与标题缺失时序，属保守策略；站点改版或未覆盖的下架形态会退回
  原 20 秒超时失败（计连续失败），不会误跳过正常商品。真实浏览器实测（真实下架商品）未执行，
  行为由实际模块的离线回归覆盖。
- 区服、商品发布时间主要来自列表卡片，详情补录不产生这两个字段——清单中的此类缺失需重新
  列表采集或删除，补录无法消缺。收藏来自详情页，登录态可见时可由补录回填。
- "数量为 0 不要求具名名单"的既有纪律保留；共鸣链/精炼在 0 五星账号看板显示"—"属正常，
  不计入缺失。
- 完整看板发起的补录依赖扩展在线（浏览器开启且扩展 ≥0.5.8）；中转任务为网关内存态，网关
  重启后需在看板重新发起。真实扩展弹窗/看板的浏览器现场点击仍未实测（browser 工具限制），
  与 docs/17、docs/18 相同，浏览器验收为离线模拟。
- 扫描扩展仅鸣潮；其他游戏的看板列扩展未做（用户指令"先只做鸣潮"）。
