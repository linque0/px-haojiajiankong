## 2. 各主题要点

### 2.4 入库字段修复与列表全文补齐（扩展 v0.4.2 → v0.4.5）

演进脉络（每版动因、做法、验证详见 docs/06）：

### 2.5 全文采集效率排查（docs/07，未改代码）

- 生产批次不能证明固定频率阈值（两次批次请求数/缓存状态不同，非对照实验）。
- 网站链路经过访问验证（列表接口有 HTTP 200 + WAF 页响应的情况），但未重现失败，不能把失败全部归因 WAF/限流。
- 现有代码可优化点 5 条（失败分类不细、每卡最多 4 次尝试、缓存仅页面内存、成功也等固定间隔、关键词卡片全部进队列）。
- 建议四阶段：诊断细分 → 跨轮缓存与只补缺项 → 列表/补齐分离 → 有证据的自适应节流。

### 2.6 列表 vs 详情浏览器对比实验（docs/08，未改代码）

- 同组 16 个鸣潮商品：列表补全文 46.420 秒仅取得 8/16（第 9 个起预检 405 → `ERR_FAILED`，扩展侧表现为 `network-error`）；串行打开详情 32.326 秒取得 16/16，快约 30% 且完整率高 1 倍。
- 已确认失败机制：预检失败（`PreflightInvalidStatus`）；405 归因（限流/访问校验/接口策略）仍需证据。
- 推荐新方案：列表只取清单和价格，缺全文商品进入详情队列，单标签页串行按就绪触发采集。

### 2.7 版本横幅诊断

- 油猴"建议更新"横幅是跨通道版本对比的误读，非 bug；看板已区分用户脚本与扩展两条更新通道，防双通道漂移。

## 4. 遗留事项与下一步（按优先级）

1. **详情队列方案落地**（docs/08 推荐）：列表采集与全文补齐分离，单标签页串行详情导航；这是当前证据下效率与完整率最优的路径。
2. **诊断细分**（docs/07 第一阶段）：失败分类结构化（timeout/invalid-json/fetch-rejected/HTTP 状态），再谈调参。
3. **跨轮缓存**（docs/07 第二阶段）：本机有界缓存公开全文，只补新增/缺失/过期，候选有效期 30 分钟起验证。
4. 在线成功率重采验证（待站点验证可通过后）。
5. 站点 405 预检失败机制补证（限流/访问校验/接口策略）。
