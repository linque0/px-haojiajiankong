# 21 鸣潮地图探索度与剩余资源估值

定位：v0.5.10 实施、v0.5.11 配置补全与口径收敛；使用说明、数据验收与模型发布门槛。日期：2026-10-07（初版）、2026-10-08（v0.5.11）。

## 改动

详情 DOM 的 `ReportCMapExploration` 保存逐地图名称、探索百分比到对应快照 JSON 的 `wuwa_map_exploration`。支持 0、小数、100；可见同名条目冲突时进度保留未知，别名统一；已有子区域时不重复计算父区域。资源配置、解析、估算、CSV、模型共用 `pxb7/exploration.py`，配置在 `pxb7/wuwa_map_resources.json`。

地图为可选字段，不进入必填查缺。列表采集复用已有详情 JSON，不覆盖地图；正常详情与补录均可写地图，补录仍在写锁内检查最新快照。余额原字段保持独立。

每张地图预计剩余量为 `资源总量 × (1 - 探索百分比 / 100)`；星声除以 160 得到抽数。没有进度/总量时保留未知，不作零值。汇总只相加能估算的区域，显示“部分地图估算”和统计覆盖率；100% 的已知区域余量为 0，100% 的未知总量仍显示未知。所有数量均标“大致估算”。v0.5.11 起仅统计星声；浮金波纹/铸潮波纹/唤声涡纹三种抽卡券在地图域不再统计（配置、估算、看板、CSV 与模型地图特征均不产出）。

完整看板筛选“鸣潮”后有可折叠地图列，展开显示四列明细及汇总。明细容器可滚动，避免 51 张地图撑成巨大的数据行。鸣潮原 CSV 末尾追加“地图探索度”“地图预计剩余资源”，原列序、文件名、BOM 保留；其他游戏不加列。

CSV 同步失败保留入库成果与旧文件。`csv-sync-status.json` 在本地 state 目录记录各游戏最后结果，完整看板与扩展弹窗可显示待同步；`POST /backfill/sync` 或“重试同步数据表”仅重新导出。同游戏后来同步成功清除提示。

v0.5.11 按满探索统计资料补全修正地图总量：`pxb7/wuwa_map_resources.json` 升为 `3.7-20261008-v2`，51 张地图全部有参考星声总量（25 张旧值按新来源修正 + 26 张补全），来源新增 `collector_stats`（逐地图满探索统计图；隐海试验场 1150、梦枢天罗 2902 为用户核对值），旧 `regional_series` 仅留档。星声统计覆盖率随之可达 51/51（有进度时 100%），`partial` 只按星声覆盖判定。余额口径“资源”列（含浮金/铸潮波纹）不受影响。改动后需重启网关以重载 `catalog()` 缓存，并重新导出看板 CSV。

## 资源配置与资料覆盖

当前详情采集平台列出 51 个地图条目，目录核对到 3.7；v0.5.11 起 51/51 全部有参考星声总量（逐地图满探索口径），全部标为近似。逐图数值、来源与口径说明见[鸣潮各地图星声数量统计](22-鸣潮各地图星声数量统计.md)；配置保留来源键与核对日期，不拆奖励获取渠道。v0.5.10 的 25 张旧值（`regional_series`，已断更来源）已被整套替换，配置中仅留档该来源键。

近似总量来自逐地图满探索 100% 社区统计图（清水代肝系列，经 233 乐园转载与读图核对）及用户核对值，不是官方精确总量；不能保证覆盖后续版本对旧图的追加奖励。全版本收入、签到奖励、限时活动不能直接当作每个账号的地图固定总量。3.7 新区域“梦枢天罗”名称按[官方 3.7 内容说明](https://mc.kurogames.com/main/news/detail/5569)核对，总量为用户提供的 2902 参考值。

覆盖率分母为配置中的叶子地图加新发现的未知地图，不只用“有总量”的地图作分母。51 张进度都有时，星声总量覆盖为 51/51（100%）；抽卡券不再统计，无对应覆盖率。

## 使用

1. 扩展详情模式采集后，在完整看板选鸣潮，点击“展开地图探索度”。地图缺失时显示未采到，可通过正常详情采集更新，不能用必填查缺清单推断地图是否缺失。
2. 已保存页面回填工具默认预览：`.venv/Scripts/python.exe -X utf8 tools/repair_wuwa_exploration.py`。应用前停止网关，加 `--apply`。工具在项目锁内检查点/备份/事务写入；备份失败不写。固定 `snapshot_round` 必须精确对应已有快照，无固定标记的旧页只允许同一轮，不跨轮猜匹配。不访问商品页。
3. 训练沿用 `tools/wuwa_valuation.py --input <鸣潮CSV> --output <新产物目录>`；检测到有效地图进度时自动进入同组地图对比。`--legacy` 强制原研究流程；旧 CSV 没地图列仍兼容。训练需含 numpy 的 Python，解析、评分与独立复算不要求 numpy。
4. 新产物 `model.json` 是按门槛决定的默认算法，`baseline-model.json`、`experimental-model.json` 分别保留；结果 CSV 展示剩余星声抽数、覆盖、两种分组留出估值、地图 log 贡献及对应人民币差额。历史 `wuwa-20261005` 目录未覆盖；`wuwa-maps-20261007` 按 v0.5.10 含券口径归档，不再用当前代码复核，v0.5.11 起地图特征不含券列。
5. 预测仍用 `tools/wuwa_valuation.py --model <model.json> --input <新CSV> --output <结果CSV>`。模型冻结资源配置，后续配置修改不改变已有模型特征口径。
6. 独立复核：`tools/verify_wuwa_exploration.py --input <训练CSV> --output <模型目录>`。核对文件 hash、组间隔离、同验证集、误差、发布门槛与结果公式。

独立复核通过，记录在产物目录 `模型验收.log`；验证源文件 hash、组间互斥、数学预测、误差和门槛。5 条不符合原资产质量要求的数据未因地图缺失而新增剔除。

## 诚实边界与应用

没有重新访问商品页，没有自动启动补录或删除，没有更改真实资源余额。v0.5.11 后 51 张地图均有参考总量但均为社区近似，抽卡券不再统计；当前估算不代表全图尚可获得的精确资源。探索百分比与奖励获取并非等比例，故仍是近似变量。

缺少卖家组、成交标签、奖励领取状态与官方逐地图总量，不能声称精确账号成交价值。测试中的验证暂停/取消/旧结果拒收继续沿用原队列回归，未新增真实站点采集演练。浏览器工具安全策略禁止进入 `chrome-extension://` 页面，不能代点扩展重载：磁盘版本已为 v0.5.11，运行中的扩展可在空闲时按原30分钟检查机制更新；也可在扩展管理页手动重新加载，再刷新详情来源页。完整看板刷新即可使用新配置。
