## 交付内容

### 1. 技术栈与合规姿态

- Python + Playwright（真实浏览器渲染采集）+ DuckDB（星型模型）+ pytest（离线测试）。
- 出网只有两处：Playwright 渲染（`pxb7/browser.py`）与 webhook 通知（`pxb7/notify.py`，urllib）；本次核对未发现 requests/httpx/aiohttp/selenium 等直连客户端（grep 命令见「验收结果 §1」）。
- **红线**（docs/01 §3.2）：不做协议逆向、不直连签名 API（`timestamp__1366=`）、不打码、不伪造指纹、不用代理池。代码中这些词只出现在声明性注释（`pxb7/browser.py:15`、`pxb7/cli.py:423`、`pxb7/__init__.py:4`）。
- 请求守卫：仅 http/https、host 白名单、拒绝环回/私有/保留地址（`pxb7/urlguard.py:86,205`）；webhook 禁重定向、启用 DNS 解析（复检消解项，见「验收结果 §6」）。

### 5. 限速与退避档位（写死在配置/代码，docs/01 §3.1/§3.3）

- 单页间隔 3–6s 随机；任务间 ≥60s；每任务每轮 ≤5 页；每任务每日 2–4 轮（settings.yaml:35-39）。
- 档位系数（乘在页间隔上，>1 = 更慢；settings.yaml:42-45）：常规（登录/游客）**1.0**；切备用 **2.0**（即频率降至 1/2，基准为常规档 1.0）；验证码后试探 **4.0**（即 1/4）。
- §3.3 六条硬逻辑（docs/01:55-62；risk.py 状态机逐条落地）：验证码/滑块 → 停采该任务 24h 后 1/4 频率试探、连续 2 次停并告警；空响应率 >30% → 当轮终止、退避 6h；IP 不可达 → 停采人工介入；主登录态被踢 → 切备用降频；主备均失效 → 降级 guest + 72h 观察后人工换号、不连续重试登录；解析成功率 <80% → 只入 raw 层继续采并告警。

## 运行方法


```bat

:: 2) 查看状态（DB 行数、词表分布、风控档位）

pxb7-price-monitor\.venv\Scripts\python.exe pxb7-price-monitor\run.py login --slot backup

:: 6) 词表入 dim_keyword（幂等）

pxb7-price-monitor\.venv\Scripts\python.exe pxb7-price-monitor\run.py extract
```

## 「每次采集只能 16 张」的定位 + 采集张数可调（2026-10-03 深夜，用户指令「给出调整采集数据条数的功能」）

### 1) 为什么是 16 张（实测结论，不是插件限制）

对四个游戏的真实列表页 raw dump 逐个数卡片：

| 列表页 dump | `[productid]` / `.middleCard` 数 | 分页控件 |
|---|---|---|
| 原神 ×4 个有效 dump | 16 | 无「下一页/分页/加载更多」元素 |
| 鸣潮 ×2 | 16 | 无 |
| 三角洲 ×2 | 16 | 无 |
| 火影忍者 ×1 | 16 | 无 |

即**站点一页在 DOM 里就渲染 16 张**，采集器只读"当前已渲染的 DOM"（设计如此：不猜 URL、
不直连接口），所以一次采集 = 16 张。且列表页里没有任何分页控件，页面用的是「滚动/懒加载」式
取更多（`t-loading__parent` 包裹列表、无 pager）。旁证：同批 dump 里还有 5 个 `[productid]=0`
的页面——那是被 WAF 挑战的拦截页（防线正确拒收，未入库）。

### 2) 新功能：每次采集张数（16–200，扩展/看板/油猴面板三入口）

- **`sweep.js`（新增，扩展）**：纯逻辑 + DOM 只读辅助——`clampTarget`（16–200）、`countCards`
  （与 parser 的 `CARD_SELECTORS` 同源：`[productid]` → `.middleCard` → 详情链接兜底）、
  `findMoreControl`（站点若渲染了「下一页/加载更多」就点它；`disabled`/`aria-disabled` 跳过）、
  `nextAction`（决策表：done-target / done-rounds / done-stalled / click / scroll）、
  `scrollForMore`（窗口或列表内部滚动容器滚到底）。**不发任何网络请求**。
- **内容脚本两段式**：先把当前页已有的 16 张立刻入库（用户马上看到结果），再在页内加载更多
  （优先点站点控件、否则滚动；每 2 秒一轮、连续 2 轮无新增即停、轮次上限 12 ≈ 192 张），
