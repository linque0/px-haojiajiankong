# 23 采集去重、变更留痕与一次自动补采

> 定位：扩展采集及本机网关的全库去重、变更版本、一次自动补采和看板历史对比。
> 日期：2026-10-08（Asia/Shanghai）。扩展 v0.5.12；油猴 v0.6.1。

## 改动

- 唯一身份为平台商品ID；不同ID不合并。同一ID跨筛选、批次和浏览器重启均查询当前数据库；更换数据库路径后使用对应库的状态。
- 扩展在请求全文和详情入队前向本机网关提交已渲染卡片，判定为新增、变化、一次缺项重试、重复跳过或待人工补录；不请求站点接口查询是否重复。最终写入在锁和事务内重新判定。
- “每次新增账号数”只计算新账号；已有账号变化及缺项重试另计。列表扫描不截断前200个候选；最多新增200号，维持2秒加载间隔、12轮上限、连续两轮没有新商品停止。目标不足明确标为部分完成。
- 列表基线与详情/完整标题分开。标准化空白、数值及结构化名单顺序。浏览人数与收藏不触发主动复采，正常浏览详情时仍记录实际观察到的值。旧库首次遇到没有基线的账号，只比较可靠的历史价格并建立列表来源基线。
- 已有缺项账号先进入详情队列；新账号首次采集后仍缺项或失败，在批次末尾自动补采一次。补采领取及结束状态存于数据库；同一任务恢复可幂等领取，其他任务不能重置已使用次数。验证码暂停不算失败、原任务续采；连续三次失败仍沿用原暂停策略。补齐后关闭缺失阶段，下次新缺失阶段可再次获得一次机会。
- 独立修订表保存真实观察时间、来源、完整字段、前一版本和字段差异；有效变化追加版本，不受30分钟轮次合并影响。未知变已知标为补齐信息；缺失值不清空已知值，数量或名单明确变化时清理旧资产明细。同轮挂牌价变化也进入价格变化事实。
- 看板默认展示采集轮次；切换“账号历史痕迹”后，每个账号一行，展开查看历史、原值/新值及每个版本的完整数据，15个版本一页。历史文本转义，自动刷新保留展开及分页状态。
- 旧库初次升级先checkpoint并备份到数据库旁的 `backups/collection-upgrade-*.duckdb`；备份失败不执行升级。按原快照导入历史基线；已被覆盖的旧标题标为未知。新增表为 `fct_listing_revision`、`collection_listing_state`、`collection_meta`。
- 原快照接口和CSV格式兼容。列表、详情、查缺补录共用历史；删除仍要求备份和人工确认，并删除关联历史和重试状态。CSV同步失败与数据库写入结果分开报告。

## 接口和使用

| 接口 | 用途 |
|---|---|
| `POST /collection/check` | 源页URL和候选DOM → 商品分类、原因、原轮次及最新修订标识 |
| `POST /collection/retry` | 商品ID、任务令牌、轮次、claim/failed/incomplete/cancelled → 一次补采领取或结束 |
| `POST /ingest/cards` | 可带明确 `selected_ids`；空数组无快照写入；返回实际接收/更新/跳过ID和逐号分类 |
| `POST /ingest/detail` | 原轮次回填，返回缺项、完整性及修订标识；补采附任务令牌 |
| `GET /listings?mode=history` | 按账号最新状态分页，返回版本数、最近变化时间与差异 |
| `GET /listings/history?id=…&offset=0&limit=15` | 按版本倒序分页返回完整数据及差异 |

重启网关，再点扩展“应用扩展更新”，刷新源列表。配置采集目标、新账号数和采集方式，点击“采集本页”。完成后检查新增、更新、重复跳过、自动重试和待补录数量。仍缺失时使用已有“信息查缺补录”。无需删除现有数据重新采集。

油猴通道共用网关去重与历史；不添加第二套主动详情队列。其缺项账号通过扩展自动补采或现有补录入口处理。

## 诚实边界

- 验证使用本地临时数据库、已有公开DOM夹具与浏览器API模拟，不启动站点采集、不操作用户现有数据。
- 列表没有显示的详情变化，只在实际浏览详情或补录时发现；没有额外定时巡检。
- 商品ID变化的重新上架账号不能自动识别为同一真实账号。
- 旧库没有保存的原始字段及同轮被覆盖的历史无法恢复，不补造。
- 离线回归不证明浏览器已加载新版、真实站点扩页效果或网站验证一定能够自动恢复。
